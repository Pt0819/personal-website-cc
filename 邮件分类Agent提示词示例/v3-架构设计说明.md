# 邮件分类系统 Agent 角色设计 v3（最终版）

## 核心理念

**明确区分：开发代理 vs 系统功能**

- **开发代理**：帮助构建系统的角色（开发阶段）
- **系统功能**：系统运行时提供的能力（运行阶段，通过提示词配置）

## 开发代理架构（3个）

## 开发代理职责

### 1. Product Agent（产品经理）

**职责**：理解需求、规划功能、制定标准

| 能力 | 说明 |
|-----|------|
| 需求分析 | 解析用户/业务需求 |
| 功能规划 | 定义系统功能模块 |
| 架构决策 | 技术选型建议 |
| 验收标准 | 定义功能验收条件 |
| 优先级排序 | 功能开发优先级 |

**输出**：
- 需求文档
- 功能规格说明
- 技术方案
- 验收标准

### 2. Go Backend Agent（Go后端开发）

**职责**：实现业务服务和数据层

**技术栈**：Go 1.21+ / Gin / GORM / MySQL / Redis

| 能力 | 说明 |
|-----|------|
| API设计 | RESTful 接口设计 |
| 业务逻辑 | Service 层实现 |
| 数据访问 | Repository 层实现 |
| 数据库设计 | 表结构、索引设计 |
| 中间件 | 认证、日志、限流 |

### 3. Agent Developer Agent（Python Agent开发）

**职责**：实现AI能力和提示词系统

**技术栈**：Python 3.11+ / LangChain / FastAPI

| 能力 | 说明 |
|-----|------|
| Agent系统 | Agent基类、编排器 |
| LLM封装 | Provider接口、多模型切换 |
| 提示词模板 | 模板系统设计（核心） |
| 工具函数 | Agent可用工具 |
| 向量检索 | Embedding + 向量库 |

**重点：提示词模板系统**

```python
# 提示词模板系统设计
class PromptTemplateManager:
    """提示词模板管理器"""

    def __init__(self):
        self.templates = {}

    def register(self, name: str, template: str, variables: list):
        """注册提示词模板"""
        self.templates[name] = {
            "template": template,
            "variables": variables,
            "created_at": datetime.now()
        }

    def get(self, name: str) -> PromptTemplate:
        """获取模板"""
        return self.templates.get(name)

    def customize(self, name: str, custom_template: str):
        """用户自定义模板"""
        self.templates[name]["template"] = custom_template
```

## 系统功能（运行时，通过提示词配置）

系统功能不通过代理实现，而是通过 **提示词模板 + 用户配置** 实现：

### 功能模板系统


## 对比：v2 vs v3

| 维度 | v2（5个代理） | v3（3个代理） |
|-----|-------------|-------------|
| **开发代理** | Product + Data + Content + Go Backend + Agent Dev | Product + Go Backend + Agent Dev |
| **系统功能** | 作为代理实现 | 作为提示词模板，用户可配置 |
| **灵活性** | 固定功能 | 用户可自定义 |
| **Token消耗** | 较高 | 较低 |
| **可扩展性** | 需要新增代理 | 只需新增模板 |

## 为什么这样设计？

### 1. 分离关注点
- **开发代理**：关注"如何构建系统"
- **系统功能**：关注"系统能做什么"

### 2. 用户可配置
- 用户可以根据自己的需求调整提示词
- 不同场景可以使用不同的模板
- 无需修改代码，只需修改配置

### 3. 更低的复杂度
- 只有3个开发代理，协作更简单
- 功能通过配置扩展，不增加代理数量

### 4. 更好的可维护性
- 提示词与代码分离
- 功能迭代只需更新模板
- 用户反馈可以直接体现在提示词调整
