# 邮件分类系统 Agent 角色设计 v4（最终版）

## 核心理念

**开发子代理 = 帮助构建系统的角色团队**

每个开发代理代表一个专业角色，各司其职、协同工作。

## 开发代理架构（4个）

```
┌─────────────────────────────────────────────────────────────────┐
│                    Product Manager Agent                         │
│                  产品经理 - 需求分析、任务拆分                     │
│                  输出: 需求文档 + 任务卡片                        │
└─────────────────────────────┬───────────────────────────────────┘
                              │
              ┌───────────────┼───────────────┐
              │               │               │
              ▼               ▼               ▼
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
│  Frontend Dev   │ │   Backend Dev   │ │  Agent Dev      │
│  Agent          │ │   Agent         │ │  Agent          │
│                 │ │                 │ │                 │
│  前端开发       │ │   后端开发       │ │  Agent开发       │
│                 │ │                 │ │                 │
│  React + TS     │ │   Go + Gin      │ │  Python + Lang  │
│  + 联调测试     │ │   + 单测        │ │  + 提示词工程    │
└─────────────────┘ └─────────────────┘ └─────────────────┘
```

## 角色职责

| 角色 | 职责 | 输出 |
|-----|------|------|
| **Product Manager** | 需求分析、任务拆分、需求文档 | PRD + Task Cards |
| **Frontend Dev** | 前端开发、API集成、联调测试 | React组件 + 联调报告 |
| **Backend Dev** | API开发、业务逻辑、单测 | Go服务 + 单测报告 |
| **Agent Dev** | Agent系统、LLM封装、提示词 | Python Agent + 单测 |

## 质量保障

| 角色 | 质量责任 |
|-----|---------|
| **Product Manager** | 需求完整性、验收标准 |
| **Frontend Dev** | 代码规范、组件测试、联调通过 |
| **Backend Dev** | 代码规范、单元测试（>70%）、接口文档 |
| **Agent Dev** | 代码规范、单元测试、提示词效果 |

## 代码规范（统一要求）

### 所有角色必须遵循

1. **错误处理**
   - 不忽略任何错误
   - 错误必须有明确的处理逻辑
   - 错误日志记录完整

2. **代码格式**
   - 使用格式化工具（gofmt / black）
   - 使用 lint 工具检查（ESLint / golangci-lint）
   - 提交前检查通过

3. **文档注释**
   - 公共 API 必须有文档
   - 复杂逻辑必须注释
   - README 说明使用方法

4. **测试覆盖**
   - 核心逻辑必须有测试
   - 测试必须可重复执行
   - 测试必须通过

## 快速开始

### 1. 启动开发流程

```
用户需求 → Product Manager 分析 → 输出需求文档
```

### 2. 获取任务列表

```json
{
  "feature": "邮件分类",
  "tasks": [
    {"id": "TASK-001", "assignee": "backend"},
    {"id": "TASK-002", "assignee": "frontend"},
    {"id": "TASK-003", "assignee": "agent"}
  ]
}
```

### 3. 并行开发

- Backend Dev: 实现 `/api/v1/emails/classify` API
- Frontend Dev: 实现邮件列表组件
- Agent Dev: 实现 Classification Agent

### 4. 联调验证

- Backend + Frontend: 前后端联调
- Backend + Agent: Agent 服务联调

### 5. 验收

- Product Manager: 验收功能是否符合需求
